fix: cumulative work, relay authentication, the peer-block lock, and verifier hygiene

Four more from the independent review, each confirmed in the code before being touched.

1. CUMULATIVE WORK WAS THE BLOCK COUNT. cumulative_work returned len(self.blocks), so a chain
   of easy blocks beat a chain of hard ones: "most work" was really "most blocks", and a miner
   who lowered the difficulty could outrun everyone by producing more headers. It now sums
   `2^256 / target` per block, which is the quantity "most cumulative work" is supposed to
   compare. A test states the inequality directly: three hard blocks outweigh ten easy ones.

2. TRANSACTION RELAY OMITTED THE P2P SECRET. relay_tx called p2p.Peer.parse(peer_text) with no
   secret, so with RADIX_P2P_SECRET set, block broadcast was authenticated and transaction relay
   was not. The receiving node rejected every relayed transaction and the sender saw only
   "unreachable" -- silent in both directions, which is the worst way for it to fail.

3. A PEER'S BLOCK WAS APPLIED OUTSIDE THE LOCK. handle_p2p mutated the chain while the miner
   could be producing a block or the state being serialised. Now under self.lock.

4. HYGIENE. Fifteen RADIX_DEBUG_VERIFY print sites were still in the verifier's reject paths,
   and tag_of, sign_tagged and verify_tagged were each defined twice in ring_signature. Both
   removed. The verifier now contains no print at all, and a test asserts that.

One existing test had to change and it is worth naming: the p2p handshake test asserted
reply["work"] == 1, which encoded the very defect being fixed. It now asserts the handshake
reports the chain's own cumulative work and that it is positive, which is what the field means.

Seven new tests. 62 tests across the chain, node, p2p and reward suites pass, and the ring
signature and tag suites are unaffected by the duplicate removal.
