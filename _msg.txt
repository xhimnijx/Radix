feat: block rewards, treasury slice and coinbase maturity

Mining paid nothing before this. A block settled the mempool and the miner received no
output at all, so the chain had no security budget and no reason for anyone to mine.

emission(height) decays linearly from 20 units to a 0.6-unit tail over 525,600 blocks
(two years at 120 seconds) and then pays the tail forever -- a fixed cap would let the
security budget decay to zero, which is why the tail exists. 10% of every reward goes to
a treasury recorded per height, and the rest to the block's coinbase recipient, which the
block now names in its header.

Maturity is enforced STRUCTURALLY rather than by a check: an immature coinbase key is not
in the ring pool, and a ring can only reference the pool. That matters because a ring
signature hides which member is real, so checking one output's age is impossible --
making every member eligible is what makes the rule sound.

TWO REAL FINDINGS, not test bugs:

1. The LWMA indices were off by one whenever the window was 1 -- the first adjustment on
   a two-block chain. Every solve time came out negative, clamped to one second, so the
   target tightened by the maximum factor on every block and the chain became unmineable
   within about twenty. It survived the synthetic tests because they only called
   next_target once the window was two or more, where the arithmetic happened to be
   right. There is now a regression test for the two-block case specifically.

2. A block reward to a reused key COLLAPSES. Output identity is the hash of (key,
   value), so two rewards paid to one key with the same value are one output; and since
   the tag is a function of the secret, that key is spendable exactly once anyway. A
   miner reusing one key accumulates one reward, not n. This is the one-time addressing
   limitation showing up in the reward path, and there is a test that asserts it rather
   than a comment that apologises for it. Every other reward test rotates keys.

Also fixed: the test fixture used the same key for the genesis allocation and the miner,
so "the miner's key is not in the pool yet" was trivially false; and key_for cycled with
period 13, so the height-1 reward key reappeared at height 92.

The wire format changed again: the block header now carries the coinbase recipient.

66 tests across the five affected testnet suites.
