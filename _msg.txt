feat: the carry and the relation mirrored in Rust, so both languages agree on balance

The carry work added two things that can silently disagree between implementations: a
committed row with no binaryness term, and a linear relation whose algebra depends on exactly
where `c` and the constant sit. A sign error or an off-by-one in the position space would pass
one side's tests and fail the other's -- which is what the two-implementation discipline is
for.

  LinearRelation in Rust      weights, signed positions, optional constant
  verify_with_relations       verify keeps its signature and passes &[] for every old caller
  Keys.carry_rows             + with_carry_rows, same pattern as the range rows
  paper_to_slot_ranged        shift is now range_count + carry_count
  request format              carry_count, the carry rows, and the relation table

Measured by experiments/cross_language_carry.py: a Python proof carrying three bit planes and
a carry message, 23,808 bytes and 23 commitment entries, is accepted by the Rust verifier;
Rust rejects it against a different message; and Rust REFUSES a proof whose carry does not
match its bits. Both languages agree on the balance relation, not just on the range term.

The existing cross-language range check still passes after the format change, and the Rust
suite is 70 passing.

One shape decision worth recording: `verify` keeps its four-argument signature and delegates
to `verify_with_relations` with an empty slice, so no existing call site, benchmark or test
changed. Adding a required parameter would have touched nine files to say nothing.
