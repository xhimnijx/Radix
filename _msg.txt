feat: a linear relation among committed messages, proven inside the proof

The primitive the m-input carry needs, and the last one missing from the range layer. C1's
eighth-pass note described it exactly: "a + b - c = f*(X-4) is linear in the committed
values, so it rides on the existing masked opening for one row."

  LinearRelation(weights, positions, constant)   sum_j weight_j * m_j - constant = 0

Positions 1..k+2m+1 are the paper's message positions; negative positions index the range
rows, so -1 is range row 0. The prover adds sum_j weight_j * a_j to psi and the verifier adds
c*(sum_j weight_j * f_j + c*constant) to the equation, which leaves exactly -c^2 * residual.
Since c must be a unit, the equality forces the residual to zero.

Five tests, and the ordering matters: a relation that holds does not disturb verification; a
relation whose constant does not match the message is REFUSED by the proof; a relation over
two messages checks their sum and is refused when both are set; and a zero weight is
documented as making the relation vacuous rather than left to be discovered.

Two errors of mine, both about what a committed message IS:

The constant's sign was wrong -- c*(sum f - c*k) instead of c*(sum f + c*k) -- which made
every relation with a non-zero constant fail. The algebra in the docstring now states the
premultiplication that makes it work rather than leaving it implied.

And the test compared ring.constant(1), which is 1 in every CRT slot, against
subring.from_constants((1,0,0,...)), which is 1 in slot 0 and 0 in the other thirty-one. Those
are different objects, so a relation that looked like it should hold did not. The helper now
documents the difference, because it is the same slot-versus-coefficient confusion that cost
a cycle in the range proof.

5 tests. This is the mechanism the carry needs; wiring the carry through it is next.
