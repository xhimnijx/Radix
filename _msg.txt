docs: bring every document up to date with the code

The documentation had drifted badly. Its most-read claims -- amounts are visible and
unproven, no consensus, no peers, B0 at 2^175, a Gaussian tail of 2^-49.5, 411 tests --
were each true when written and none is true now. This round reconciles them.

  one-time addressing             the derivation works; the wallet does not use it
  noise-aware statement           wired at ell = 17
  network                         HMAC transport, two-hop discovery, slow start,
                                 checkpointed sync
  B0                              2^167, not 2^175, because k' = 1 shrank W
  Gaussian                        12 sigma: 2^-107.8 per coefficient, max sample 31986

Two were factually wrong rather than merely old, and are the kind of error a reader would
act on:

- CLAUDE-TRANSACTIONS said the digit vector occupies the first 32 of 128 coefficients. It is
  CRT-lifted, one bit per slot, and that distinction is exactly the bug that cost a debugging
  cycle -- a coefficient-constant polynomial is not a slot-constant one.
- ALPHA-SLOTS predicted W would grow from 30 to ~50 and the range layer would cost ~42 KB.
  Measured: W does not move at all, because a range row is an ordinary BDLOP row reusing the
  same randomness. The cost is 512 bytes per bit polynomial.

Also normalised the test counts (385, 404, 411, 558 and 569 all appeared; the answer is 603),
and recorded the verify time as 106-110 ms across runs rather than pretending to one number.

Each correction says what it replaced where that matters, so the record shows what moved
rather than quietly rewriting history.
