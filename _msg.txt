feat: genesis is a protocol constant, so two nodes agree without talking

Before this the genesis allocation came from whatever wallet the node happened to create,
so two independently started nodes were on different chains and the sync had to transmit
an allocation list together with the chain -- a shortcut recorded in p2p.py. The
consequence was structural: a network only worked if every node was handed the same
wallet, which is not a network anyone can join.

Block zero is now derived from GENESIS_MNEMONIC in params.py, and the phrase is the
standard BIP-39 test vector -- 'abandon abandon ... about'. That choice is the point: it
is unmistakably public, and the docstring says plainly that anyone reading the file can
derive the keys and spend the genesis coins. That is a faucet, not a launch. A mainnet
needs an allocation specified and audited before genesis, and a published phrase must not
be carried forward.

The sync payload no longer carries 'allocations'. A receiver derives the allocation from
the protocol, so a peer cannot hand us a chain whose block zero pays a different set of
keys -- which is what the earlier per-node allocation would have permitted.

Measured: two nodes created in separate temporary directories, with no communication,
produce the same genesis hash, hold the same faucet key, and see a balance of 4000.

One stale assertion surfaced: the node status test still expected tag_rows == 4, which has
been 1 since the k' change. It was failing for a reason unrelated to this work, and it is
worth noting that a parameter change left a test asserting the old value rather than
failing loudly at the time.
