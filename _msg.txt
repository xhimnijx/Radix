feat: value commitments, so balance is checkable without revealing amounts

radix_testnet/amounts.py: C = G*a + B*r over R_q, with G a kappa-vector, B a kappa x kappa matrix, both derived deterministically from a label so every node gets the same parameters, and r uniform so the commitment hides.

Additively homomorphic by construction, which is what makes the balance equation work: sum of input commitments minus sum of output commitments minus the fee commitment must be the zero vector. The sender sets the output randomness to sum to the input randomness; a sender who wants an unbalanced transaction cannot satisfy that without opening a commitment, which is a module-SIS problem.

9 tests: opens to its amount; two commitments to the same amount differ (hiding); homomorphic under addition; an honest 2-in/1-out balance passes; an inflated output is rejected; a fee off by one is rejected in both directions; mismatched randomness is rejected; an amount at q is refused.

TWO LIMITS, both tested rather than described.

The first is that amounts must be below q, about 2^32, because the amount is a single coefficient. The paper does not have this ceiling because it encodes amounts as 32 base-4 digits covering 64 bits -- and those digits are also why it needs a carry proof, which is reference [25]. This module deliberately takes the linear, carry-free encoding and inherits the ceiling.

The second is that there is no range proof. A commitment to q-100 is a perfectly valid commitment, indistinguishable from -100, so a sender can mint money. test_the_known_limitation_a_negative_amount_is_indistinguishable asserts exactly that, so the gap cannot be forgotten or quietly closed by a comment.

So this makes balance checkable. It does not make value safe, and STATUS.md says so.
