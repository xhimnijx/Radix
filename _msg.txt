feat: the range statement, as one verifier

All the primitives existed separately -- base-4 digits, bit packing, slotwise binaryness,
the carry relation, the relaxed bound. range.py assembles them into one object and one
verifier, so the statement is defined rather than described and the proof that will
replace `verify` has a specification to hit.

Five things checked, and each is necessary: every bit is a bit (b(b-1)=0 slotwise);
every digit is 2*b1+b0, which ties the committed bits to the committed digits; every digit
is in {0,1,2,3}; the digit polynomials add up with an explicit carry; and the carry is
small. Drop the third and a prover commits honest bits with dishonest digits. Drop the
fourth and every amount is individually in range while the transaction still mints.

`verify` takes the witness in the clear, so it is a specification rather than a proof --
it exists so the proof's obligations are written down and tested before the alpha-slot
layout is attempted. That is stated in the module docstring rather than implied.

A verifier rejects malformed input rather than raising on it: an exception tells a caller
something went wrong, a return value tells them the statement is false, and only the
second is a verdict. Caught by a test that expected False and got a DigitError.

9 tests, including that an unbalanced statement is refused even when every amount is
individually in range.
