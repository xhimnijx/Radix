fix: three currency-breaking defects an independent review found

An independent review put the project at ~18%, against my ~80%, and it was right on the four
defects that matter. My scoring table had no line for supply integrity, so it measured progress
against the plan I had rather than against what a currency requires. Three of the four were
fixable today and are fixed here.

1. THE BLOCK HASH DID NOT COMMIT TO THE TRANSACTIONS. The header carried
   `str(len(transactions))`, so two blocks with completely different spends and the same count
   had the SAME HASH. Proof of work secured an ordering of block hashes rather than a ledger:
   publish a block, then publish a different block with the same hash and the same work, and
   every peer treats it as the same block. The header now carries a transaction root -- a
   SHA3-256 over every payload, each hashed canonically and SORTED so the root depends on the
   set of spends rather than their arrival order. Tests cover both directions: different spends
   differ, and the same set in a different order does not.

2. A PEER'S BLOCK WAS APPLIED WITHOUT VERIFYING ITS TRANSACTIONS. node.py called
   `self.chain.append(block)` and append defaults to `verify_transactions=False`, which is right
   for locally mined blocks and wrong for a stranger's. A miner could push arbitrary unsigned
   spends into every peer. The call site now passes True, with a comment saying why. The default
   stays False and is asserted so, because changing it would silently re-verify every local block.

3. PERSISTENCE DROPPED THE STATE THAT MATTERS. chain_to_dict wrote height, previous, anchor,
   transactions, nonce and timestamp -- and nothing else. Omitting `minted` reset the supply cap
   to zero on every restart, which is the same as not having one. Omitting `target` lost the
   difficulty history, so a restarted node computed a different next_target and rejected valid
   peer blocks. Omitting `coinbase` stranded every immature reward permanently. Omitting
   `immature` and `treasury` lost balance-relevant state. All five now persist, and a round trip
   is tested against minted, every target, every coinbase, maturity, treasury and next_target.

Eight tests in tests/test_testnet_integrity.py. 74 tests across the chain, node, p2p, reward,
genesis and checkpoint suites still pass.

NOT FIXED, and it is the one that matters: value is not bound to notes. `input_values` is
self-declared and nothing checks it against the note being spent, so a wallet can claim a
billion atoms from a four-thousand-atom genesis. The reviewer demonstrated it end to end. That is
the same defect as the unfinished range/balance research recorded in REVIEW-FINDINGS, and it is
not something to patch -- it needs the value-commitment layer, which needs the bridge.
