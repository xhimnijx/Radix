docs: an implementation-study draft, with its claims and limitations fixed first

docs/PAPER.md. The order is deliberate: claims, then limitations, then the prose. A paper
whose scope is decided by what it manages to write ends up overclaiming; one whose claims
are listed first cannot.

Five claims, and nothing outside them: the protocol is implemented twice and each accepts
the other's proofs; 21,760 bytes at ring size 1024; 475 ms to prove and 105.8 ms to verify;
four reproducible defects; and a delta-model estimate of 2^158 and 2^167.

Not claimed, and said so in the paper: any security level, because the estimate is a delta
model rather than an estimator run, the restatement is signed by a reviewer but not proved
here, and the implementation is unaudited.

The defects table is the paper's heart, because it is the argument for the method. Four
defects, none findable by reading, two of them found only because a second implementation
disagreed with the first. The commitment arity is the best example: κ+λ+m+1 and
κ+rows+2m+1 agree exactly when rows = 8, so a test suite built on one configuration cannot
distinguish them.

Sections are headings with the measured numbers filled in and TODOs where prose is missing.
That is honest about what exists: a skeleton good enough to write into, not a paper.
