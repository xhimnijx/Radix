feat: ell = 17 works end to end, which the noise-aware statement requires

C1 and C2 both said the same thing in different words: A_noise = [A | I_k] has ell + k = 17
columns where the default is 13, so the statement, keys, prover and verifier must all run
at that width. Two hardcoded checks made it impossible to construct anything at a width
other than the default:

  Parameters.__post_init__ validated A's rows against SMILE.matrix_cols
  Statement.__post_init__ did the same

Both now derive the width from the rows they are given, so a statement is self-consistent
rather than pinned to a global default. That is the correct rule anyway: a Statement that
validates its own shape should not be consulting a module constant.

A full prove and verify at ell = 17 now completes: 22,784 bytes, z' with 17 components,
accepted against the right message and rejected against a different one. The test is marked
slow because it produces a real proof (140 s).

Also generated the Gaussian table for width 17, since z' is masked at sigma = 464*sqrt(17)
and the sampler refuses widths it has no table for -- which is the behaviour that was
designed in, and it caught this correctly rather than substituting a nearby distribution.

This is a prerequisite, not the statement itself: the proof at ell = 17 proves the plain
SMILE relation over a 17-column matrix. Wiring the [A | I_k] split into the witness and the
tag rows [A' | 0] is the next step, and the extraction argument for it is C1's.
